<task type="auto">
  <name>Task 2: Create configuration logic (gsd-configure)</name>
  <files>bin/gsd-configure</files>
  <action>
Create the configuration application script at `bin/gsd-configure`. This script implements the step-by-step configuration:

1. Per D-05: State file location is `.gsd/state.json`
2. Per D-06: State tracks current phase, applied permissions, configuration version
3. Per D-07: Include schema version for future migrations

Configuration steps:
- Step 1: Install OpenCode + basic security defaults
- Step 2-4: Progressive permission expansion

Per D-08: Default permissions are restrictive — ask before read, deny by default for write operations
Per D-09: Auto-update disabled by default ("autoupdate": false)
Per D-10: External directory access restricted to explicitly configured paths only
Per D-11: Destructive commands require explicit confirmation (rm -rf prompts)
Per D-12: Permission wildcards expand to specific paths, never full home directory

Implementation:
- Read current state from .gsd/state.json (create if doesn't exist)
- Validate --step value (1-4)
- Apply configuration for the requested step
- Update state.json with new phase and applied permissions
- Output colored status messages
</action>
  <verify>
chmod +x bin/gsd-configure && ./bin/gsd configure --list</verify>
  <done>
- gsd configure --step 1 applies step 1 configuration
- gsd configure --step 2 applies step 2 configuration
- State file .gsd/state.json is created/updated
- Colored output shows current step and status
  </done>
</task>
