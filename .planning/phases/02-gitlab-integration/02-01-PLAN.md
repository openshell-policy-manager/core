Create GitLab authentication script at `bin/gsd-gitlab`. This script handles Deploy-Token configuration per D-01:

1. Per D-01 (from CONTEXT): Use Deploy-Token method - simpler than OAuth, more secure than long-lived tokens

- Validate token format (glpat-*) before storage
- Add GitLab host to network whitelist automatically
- Update .gsd/state.json with gitlab_token set to "configured"

Per GITL-01: Configure GitLab OAuth/Deploy-Token
Per GITL-04: Credentials stored securely without override

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | gitlab-deploy-token | mitigate | chmod 600 on credentials file, validate token format |
| T-02-02 | Information Disclosure | credentials file | mitigate | Store in separate dir (~/.config/opencode/credentials/), not ~/.git-credentials |
| T-02-03 | Spoofing | network rules | mitigate | Validate domain format before adding to whitelist, reject wildcards except * |
| T-02-04 | Elevation of Privilege | --step flag | mitigate | Validate step is 1-4 in gsd-configure |
| T-02-05 | Denial of Service | network rules | accept | pfctl rules are system-level, low risk |
</threat_model>
