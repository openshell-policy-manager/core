Implementiere den dedizierten Dry-Run Modus gemäß D-04, D-05, D-06:

1. **Füge `--dry-run` Flag hinzu:**
   - Kann mit jedem `--step N` kombiniert werden
   - Zeigt detaillierte Auflistung der Änderungen OHNE sie anzuwenden
   - Zeigt Bestätigungsaufforderung (aber führt nicht aus)

2. **Erweitere die Ausgabe:**
   - Zeige alle Konfigurationsänderungen die angewendet würden
   - Formatiere mit BLUE für "[DRY-RUN]" Prefix
   - Zeige "No changes will be made" Disclaimer

3. **Integration mit bestehendem `--verify`:**
   - Behalte `--verify` als Alias für `--dry-run`
   - Dokumentiere beide Flags in der Hilfe

Beispiel-Ausgabe:
```

[DRY-RUN] Would apply step 3: Skills & Sandbox

Configuration that would be applied:
  - Set current_phase to 3
  - Add step_3 to applied_steps
  - Configure OpenCode skills from config.json
  - Enable MCP servers

No changes have been made. Run without --dry-run to apply.
```
  </action>

<task type="auto">
  <name>Task 3: Export/Import Funktionalität implementieren</name>
  <files>bin/gsd-configure</files>
  <action>
Implementiere Export/Import gemäß D-07, D-08, D-09, D-10:

1. **Export (`--export <file>`):**
   - Exportiere state.json Inhalt
   - Inklusive: Konfigurationsversion, aktive Phase, angewendete Schritte
   - Optional: Netzwerk-Whitelist aus network-rules.json
   - Optional: Skills-Liste falls config.json existiert
   - JSON Format mit pretty-print

2. **Import (`--import <file>`):**
   - Lade JSON Datei
   - Validierung: Version-Check (schema_version muss "1.0" sein)
   - Validierung: Schema-Validierung (Pflichtfelder prüfen)
   - Überschreibt state.json nach Bestätigung
   - Backup der alten Konfiguration erstellen

3. **Sicherheit:**
   - Import fragt nach Bestätigung bevor überschrieben wird
   - Backup-Datei mit timestamp erstellen (.gsd/state.json.backup.YYYYMMDD)
   - Fehlermeldung bei ungültigem Format oder Version

Beispiel Export:
```json
{
  "version": "1.0.0",
  "exported": "2026-04-05T12:00:00Z",
  "phase": 2,
  "applied_steps": [1, 2],
  "permissions": {...},
  "network": {...},
  "skills": [...]
}
```
  </action>
  <verify>
    <automated>bin/gsd configure --export /tmp/test-export.json && test -f /tmp/test-export.json && python3 -c "import json; json.load(open('/tmp/test-export.json'))"</automated>
  </verify>
  <done>Export erstellt gültige JSON-Datei. Import validiert und stellt Konfiguration wieder her.</done>
