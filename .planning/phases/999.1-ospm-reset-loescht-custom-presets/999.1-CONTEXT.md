# Phase 999.1: ospm-reset-loescht-custom-presets - Context

**Gathered:** 2026-04-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Add `ospm preset reset` command that removes downloaded presets and templates from `~/.config/ospm/`, restoring the delivery state by re-downloading from GitHub. Only ospm-owned directories are touched. The `--all` flag additionally removes `~/.oshell-config/`.

</domain>

<decisions>
## Implementation Decisions

### Command structure
- **D-01:** Command name: `ospm preset reset` (sub-command under `preset`, aligns with existing `ospm preset update`)
- **D-02:** Default: resets presets + templates in `~/.config/ospm/`
- **D-03:** `--all` flag: additionally removes `~/.oshell-config/` for a complete reset

### Reset scope
- **D-04:** Deleted on default reset: `~/.config/ospm/presets/` (entire directory), `~/.config/ospm/templates/` (entire directory)
- **D-05:** Kept on default reset: `~/.config/ospm/defaults.yaml` (user's preferences preserved)
- **D-06:** Deleted with `--all`: additionally `~/.oshell-config/` directory

### Delivery state
- **D-07:** "Delivery state" = fresh download from `openshell-policy-manager/presets` GitHub repo
- **D-08:** After deleting presets/templates, automatically call `ospm preset update` to re-download
- **D-09:** Re-download uses existing `UpdatePresets()` function from `internal/config/presets.go`

### Confirmation
- **D-10:** Always asks for confirmation before deleting — no `--force` flag to skip
- **D-11:** Confirmation shows what will be deleted (list of paths + approximate count of files)
- **D-12:** Uses existing `VerifyPathsExist()` pattern from `internal/config/cleanup.go`

### No-presets edge case
- **D-13:** If no presets exist (directory doesn't exist): print warning, exit with code 1
- **D-14:** Do not attempt to re-download if nothing exists to reset

</decisions>
