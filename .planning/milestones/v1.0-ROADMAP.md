## Phase Details

### Phase 1: Base Configuration

**Goal**: CLI tool exists and functions with secure base configuration

**Depends on**: Nothing (first phase)

**Requirements**: INST-01, INST-02, INST-03, BASE-01, BASE-02, BASE-03, BASE-04, BASE-05, CLI-01, CLI-02

**Success Criteria** (what must be TRUE):

1. User can install OpenCode via `brew install opencode` or direct download
2. User can read and follow the installation guide step by step
3. CLI command `gsd configure --step N` exists and starts configuration
4. CLI command can gradually unlock permissions with `--step 1`, `--step 2`, etc.
5. Configuration uses secure defaults (no permissive rights)
6. Auto-update is disabled by default
7. External directory access is restricted
8. Destructive commands (rm -rf) require confirmation

### Phase 2: GitLab Integration

**Goal**: GitLab access works with secure network configuration

**Depends on**: Phase 1

**Requirements**: GITL-01, GITL-02, GITL-03, GITL-04, NETW-01, NETW-02, NETW-03

**Success Criteria** (what must be TRUE):

1. User can store GitLab OAuth token in the configuration
2. User can read GitLab repositories from OpenCode (clone, pull)
3. User can write to GitLab repositories (push, commit)
4. GitLab credentials are stored securely without overwriting existing credentials
5. Network access to gitlab.com is allowed
6. Free internet access for web research is enabled
7. Only data from explicitly approved sources is downloaded

### Phase 3: Skills & Sandbox

**Goal**: OpenCode skills and MCP servers are configurable

**Depends on**: Phase 2

**Requirements**: SAND-01, SAND-02, SAND-03, SAND-04, SAND-05, SAND-06

**Success Criteria** (what must be TRUE):

1. OpenCode sandbox can be set up with configurable skills
2. MCP servers approved in OpenCode can be used
3. Websearch/Webfetch skills are usable
4. Codesearch skill is usable
5. File operations skills are usable
6. Git operations (status, diff, commit) are usable
